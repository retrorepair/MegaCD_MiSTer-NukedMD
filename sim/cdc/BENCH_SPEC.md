# CDC verificator ground truth — for the ModelSim bench

Source of truth: `verificator/test_cdc_new.c` (the real suite `testCDC_new`), `mcd.c`/`mcd.h`, `sub_bios.s`, `cdd.c`; cross-checked against `rtl/MCD/CDC.vhd` and `rtl/MCD/ASIC.vhd`. The headers `cdc.h`/`pcm.h`/`sys.h` are **absent** from the extract, so the `cdc*`/`CDC_*`/`IFCTRL_*` symbols are **reconstructed** and then **validated** against the inline equivalents that appear in the test itself (`tsetCDC_end`, the "continue dma" block at 772-778, the inline `FF8005/FF8007` writes in `testCDC_init`) and against the CDC.vhd register map. Confidence is noted per item.

## A. The two buses the bench must drive

The verificator runs on the **MAIN** 68000 (Genesis cart). Two access paths:

- **MAIN / EXT bus, `$A120xx`** — direct MMIO through `ga = 0x0A12000` (`mcd.c:6`) and the `REG*_A1200*` macros (`mcd.h:4-6`). In the RTL these are `EXT_*` cycles into ASIC (`ASIC.vhd:509` `M68K_GA_SEL`, decode at 543-707). The bench drives `EXT_VA/EXT_VDI/EXT_AS_N/EXT_RNW/EXT_UDS_N/EXT_LDS_N/EXT_FDC_N`.
- **SUB / S68K bus, `$FF80xx`** — every `mcdWR8/WR16/RD8/RD16(0xff80xx,...)` (`mcd.c:106-136`). On real hardware the MAIN posts these to the sub-CPU over the COMCMD mailbox and the `sub_bios.s` stub executes the `FF80xx` cycle (`sub_bios.s:100-118`). **The bench has no sub-CPU**: each `mcdWR8/RD16(0xff80xx)` becomes a direct **S68K bus cycle** into ASIC (`ASIC.vhd:773` `S68K_GA_SEL`, decode 895-1146+). Drive `S68K_A/S68K_DI/S68K_AS_N/S68K_RNW/S68K_UDS_N/S68K_LDS_N`.

**CDC register access is generated by ASIC, not addressed directly** (`ASIC.vhd:2580-2584`):
```
CDC_N  <= '0' when S68K_A(19:2)=x"F800"&"01" and S68K_LDS_N='0' and S68K_AS_N='0' else '1';
CLWE_N <= S68K_LDS_N or S68K_RNW;                       -- CDC WR_N
COE_N  <= (S68K_LDS_N and S68K_UDS_N) or not S68K_RNW;  -- CDC RD_N
```
CDC `RS = S68K_A(1)`, CDC `DI = S68K_DO(7:0)`. So:
- `FF8005` (odd byte, A(1)=0) → CDC **RS=0 = register-address (AR)** port.
- `FF8007` (odd byte, A(1)=1) → CDC **RS=1 = register-data** port.
- `FF8004` (even byte, UDS) is **not** CDC — it hits the ASIC `DD`/mode register (`ASIC.vhd:912-917`).

So a faithful sub-side register write is a single S68K byte cycle to the odd address; the bench does **not** need to model the CDC chip-select itself — feeding S68K into the real ASIC produces `CDC_N/COE_N/CLWE_N/RS` for free.

## C. Helper functions (reconstructed, validated)

All validated against inline equivalents in the test, so these are high-confidence:

```c
cdcRegSelect(r) : mcdWR8(0xFF8005, r)        // S68K byte -> AR      (== test:76,114 inline)
cdcRegWrite(v)  : mcdWR8(0xFF8007, v)        // S68K byte -> data    (== test:77,115 inline)
cdcRegRead()    : mcdRD8 (0xFF8007)          // S68K byte <- data    (== test:95-99)
cdcDTTRG()      : mcdWR8(0xFF8007, 0)  with AR==6   (== the many "mcdWR8(0xff8007,0);//dttrg")
cdcDTACK()      : cdcRegSelect(0x07); cdcRegWrite(0)  // clears DTEI (CDC.vhd:509-511)  [reconstructed]

cdcDmaSetup(dd, len, pt):                    // VALIDATED by the "continue dma" block test:772-778
    mcdWR8 (0xFF8004, dd);                    // ASIC: DD<=dd&7; DMAA<=0; DMA_ADDR_SET pulse
    mcdWR8 (0xFF8005, CDC_DBCL);              // AR=2
    mcdWR8 (0xFF8007, (len-1) & 0xFF);        // DBCL   (DBC register = bytecount-1)
    mcdWR8 (0xFF8007, (len-1) >> 8);          // DBCH   -> AR=4
    mcdWR8 (0xFF8007, pt & 0xFF);             // DACL
    mcdWR8 (0xFF8007, pt >> 8);               // DACH   -> AR=6 (DTTRG), ready for the caller's dttrg
```
`DBC = len-1`, transfers `len` bytes (init: `len=2352`→DBC=2351→2352 bytes read; CDC.vhd byte counter 589/597). `cdcDecoderON/OFF` (test:78/107) are reconstructed as: ON = `IFCTRL=DECIEN|…`, `CTRL0=DECEN`, `CTRL1=SYIEN|SYDEN` (mirror of test:1168-1172); OFF = `CTRL0=0`. The precise ON body is not in the extract — but for the bench what matters is DECEN=1 + SYIEN so the frame timer + sector decode run.

## D. `while (ga->COMSTA[3] != 5)` — the model the bench MUST supply

`ga->COMSTA[3]` = **`A12026`** = `CS(3)` (struct offset 0x20+6). On hardware it is written by the sub-BIOS ISRs: **`IE5` (level 5 = CDC) writes 5** (`sub_bios.s:190-191`), and `cmd_rx` clears it to 0 at the top of **every** mcd bus command (`sub_bios.s:64` `move.w #0, STA_IRQ.w`, STA_IRQ=0x8026). So:

> `while(ga->COMSTA[3]!=5)` == "block until the **next CDC level-5 interrupt** since the last mcd command."

Level-5 path in RTL: `CDC.vhd:645` `INT_N <= (DTEI or !DTEIEN) and (DECI or !DECIEN)` → `CDC_INT_N` falls when DTEI→0 (DMA done, `CDC.vhd:600`) with DTEIEN=1 → `ASIC.vhd:1306-1307` sets `INT_PEND(5)` → `ASIC.vhd:2520` `INT_IPL="101"`. **The bench, having no sub-CPU, must emulate `COMSTA[3]`**: reset its model to 0 on every S68K "command", and set it to 5 when `CDC_INT_N` falls (or `INT_PEND(5)` rises). This is the single most important non-register piece of state the bench fakes — get it wrong and every memory-DMA wait is meaningless.

## F. INIT (`testCDC_init`, test:61-133) — loads the reference sector, returns `PT`

1. `cddInitToc()` (cdd.c:61) — IEMASK=`(1<<4)`, HOCK (`FF8036=4`), CDD `nop`+`getToc`, wait TOC. *(drive/CDD path.)*
2. **Reset CDC**: `mcdWR8(0xFF8005,CDC_RST); mcdWR8(0xFF8007,0)` (AR=15 write → CDC soft reset).
3. `cdcDecoderON()` — DECEN=1 so sectors decode into the CDC buffer RAM.
4. IEMASK=`(1<<4)`; `cddCmd_play(0x173)`; `cddUpdate×2` — play from the sector whose header is `00:02:00` (disc LBA0, the Sega security/volume sector).
5. IEMASK=`(1<<5)` (CDC irq). Loop (test:88-104): `mcdRD16(0)` resets COMSTA[3]; inner `while(ga->COMSTA[3]!=5)` (timeout 20000 → **err 0x02**); then read header:
   `cdcRegSelect(CDC_HEAD0)` then 6×`cdcRegRead()` → `head = H0<<24|H1<<16|H2<<8|H3`, `*PT = PTL | PTH<<8`.
   **Break when `head==0x00020001`**; `i>=200` → **err 0x03**.
6. `cdcDecoderOFF`; stop; `IFCTRL=DOUTEN|DTEIEN` (`FF8005=1;FF8007=0x42`).
7. `cdcDmaSetup(CDC_DST_MAIN, 2352, *PT)`; `mcdWR8(0xFF8007,0)` dttrg; 16 nops; read 2352 bytes via `REG16_A12008` into `buff` (test:121-124).
8. Compare `buff[0..7] == {00,02,00,01,'S','E','G','A'}` (test:126); mismatch → **err 0x04**.

**Fidelity requirement:** the bench must feed, via `CDC_DATA`/`CDC_DAT_WR` (=`CD_DI`/`CD_WR` into CDC.vhd, wired in `MCD.vhd:415-416`, driven in the real core from ioctl idx 0x02 → `cdc_dat_download`), a real 2352-byte Mode-1 sector with **12-byte sync (bytes 0-11), header{min=00,sec=02,frame=00,mode=01} at bytes 12-15, "SEGA…" from byte 16**. CDC.vhd decode (359-414) captures header at `WORD_CNT=6/7` (offset 12/14) into `HEAD0..3`, writes header+2048 data into the buffer at `PT+2352+RAM_POS` (with `WRRQ=1`), and advances `PT+=2352` at sector end (405-411). The returned `*PT` then points exactly where the DMA reads. Byte-order within each 16-bit `CD_DI` word must match `MegaCD.sv` `cdc_dat` packing — calibrate against `buff[0..7]`.

## G. FLAGS (`testCDC_flags`, test:1030-1322) — **ERROR 05**

`IFCTRL=DOUTEN|DTEIEN`. First block "only reg FF8004 can reset EDT" (test:1046-1064):
```
mcdWramToSub(); cdcDTACK();
cdcDmaSetup(CDC_DST_WRAM, 2352, PT); mcdWR16(0xFF800A, 0); mcdWR8(0xFF8007,0);  // WRAM DMA
while (ga->COMSTA[3] != 5);                    // wait DMA complete -> EDT legitimately set
cdcDTACK();
if ((REG08_A12004 & EDT)==0) return 0x01;      // EDT must be SET after a WRAM DMA
mcdWR16(0xFF800A, 0);                            // FF800A write
if ((REG08_A12004 & EDT)==0) return 0x02;      // EDT must SURVIVE FF800A
cdcRegSelect(CDC_IFCTRL); cdcRegWrite(0);       // IFCTRL=0
if ((REG08_A12004 & EDT)==0) return 0x03;      // EDT must SURVIVE IFCTRL=0
cdcRegSelect(CDC_RST);    cdcRegWrite(0);       // CDC reset
if ((REG08_A12004 & EDT)==0) return 0x04;      // EDT must SURVIVE CDC reset
mcdWR8(0xFF8004, CDC_DST_WRAM);                 // FF8004 write
if ((REG08_A12004 & EDT)!=0) return 0x05;      // EDT must now be CLEAR  <-- FAILS on build 36
```
**Why 05 on current HEAD:** the reverted RTL makes EDT a *live idle view*, not a latch — `ASIC.vhd:419` `EDT<='1'` in `DS_IDLE` whenever `CDC_DTEN_N='1'` (i.e. always, when idle). `DMA_ADDR_SET` (FF8004/FF800A) drives `EDT<='0'` for one cycle (`ASIC.vhd:400`) but `DS_IDLE` re-asserts it next cycle. So checks 01-04 **pass** (EDT keeps bouncing back → survives FF800A/IFCTRL/RST) and check 05 **fails** (FF8004 can't hold it cleared either). Fix `ccb6fdf` makes EDT a latch set on the `DTEN_N` 0→1 edge and cleared only by a FF8004-armed `DMA_EDT_CLR` (so FF800A no longer clears it — that is what keeps 02 passing).

Rest of FLAGS (build 36 passes all of these, they run after 05 returns only in a fixed build; on build 36 the function returns at 05): DMA termination 0x11/0x12 (1071-1083); IRQ-after-DMA 0x20/0x21/0x22 to MAIN (1087-1108); IRQ after WRAM/PRG/PCM 0x23/0x24/0x25 (1112-1135); DTEI-edge IRQ 0x26/0x27 (1139-1163); decoder-IRQ suite 0x30-0x35 (1168-1231); DECI phase 0x40/0x41 (≈49 and ≈72 IFSTAT polls, 1234-1265); DECI-on-decoder-off 0x42/0x43/0x44 (1268-1298); word-only `FF800A` access 0x46/0x47 (1300-1306).

## H. DMA2 (`testCDC_dma2`, test:411-564) — **ERROR 05**

Word-RAM / PRG / PCM DMA addressing + odd-length. The two WRAM odd-length cases:
```
// 0x04 : odd len - 1  (test:445-459)
cdcDmaSetup(CDC_DST_WRAM, (2352-2)-1 /*=2349*/, PT); ...dttrg; while(COMSTA[3]!=5);
compare word_ram vs buff; if (i != 2348) return 0x04;      // 2349 bytes = odd -> last byte dropped

// 0x05 : odd len + 1  (test:462-476)
cdcDmaSetup(CDC_DST_WRAM, (2352-2)+1 /*=2351*/, PT); ...dttrg; while(COMSTA[3]!=5);
compare word_ram vs buff; if (i != 2350) return 0x05;      // expect exactly 2350 bytes written
```
`len=2349`→DBC=2348→**2349 bytes** (odd) → drops the dangling byte, 2348 written, `i==2348` ✓. `len=2351`→DBC=2350→**2351 bytes** (odd) → expect 2350 written, `i==2350`.

**Why 05 on current HEAD:** the WRAM word assembler (`ASIC.vhd:426-435`) toggles `DMA_BYTE` to build 16-bit words. The 0x04 transfer (2349 bytes, odd) ends with `DMA_BYTE='1'` (high byte latched, low byte never arrives). The reverted RTL does **not** reset `DMA_BYTE` on `DMA_ADDR_SET`, so the 0x05 transfer starts **mid-word**, mis-assembling and mis-counting → it writes 2352 bytes instead of 2350, the compare matches all 2352, `i==2352 != 2350` → **return 05**. (Note 0x04 passes precisely because it runs first with `DMA_BYTE=0`.) Fix `ccb6fdf`: `DMA_BYTE<='0'` on `DMA_ADDR_SET` so every DMA starts word-aligned (matches GPGX-408/jgenesis-105).

Preceding/following DMA2 checks (all pass build 36): 8-byte-offset WRAM 0x01/0x02/0x03 (1422-441); PRG-RAM 0x06-0x10 (479-538, same odd-length pair 0x09/0x10 expecting 2348/2350); PCM 9-byte len 0x11/0x12 (540-559).

## I. DMA3 (`testCDC_dma3`, test:566-1028) — **ERROR 01; the disc-present HANG**

**Section 1 — host-data DMA to MAIN (the crux, test:578-596):**
```
cdcDmaSetup(CDC_DST_MAIN, 2352, PT);                   // FF8004 DD=2 -> DMA_ADDR_SET (EDT<=0 1 cyc), DBC=2351, DAC=PT
if (REG08_A12004 != 0x02) return 0x01;                 // EDT=0,DSR=0,DD=2   <-- FAILS on build 36 (reads 0x82)
mcdWR8(0xFF8007,0);                                     // DTTRG (AR=6) -> CDC starts host xfer
for(i=0;i<4;i++)nop;
if (REG08_A12004 != 0x42) return 0x02;                 // DSR set, EDT clear
for(i=0;i<2352-4;i+=2) tmp = REG16_A12008;             // read 2348 bytes (1174 words) via A12008
if (REG08_A12004 != 0x42) return 0x03;                 // still only DSR while >=2 words remain
tmp = REG16_A12008;                                    // 1 more word -> 2 bytes remain
if (REG08_A12004 != 0xC2) return 0x04;                 // EDT+DSR when last word remains
tmp = REG16_A12008;                                    // last word
if (REG08_A12004 != 0x82) return 0x05;                 // EDT only, all read
tmp = REG16_A12008;
if (REG08_A12004 != 0x82) return 0x06;                 // no change on extra read
if (mcdRD8(0xFF8004) != 0x82) return 0x07;             // same state visible on sub side (FF8004)
```
Host read is `A12008`→`ASIC.vhd:659-661` returns `HD`, sets `MAIN_CPU_CDC_READ='1'` (releases `DS_WRITE_WAIT`, `ASIC.vhd:466-469`) and always DTACKs — an `A12008` read never bus-hangs.

**Why 01 on current HEAD:** `cdcDmaSetup(MAIN)` ends with the `FF8004` write → `DMA_ADDR_SET` → `EDT<='0'` for one cycle, but the live-idle logic (`ASIC.vhd:414-419`, `CDC_DTEN_N='1'` because no transfer is running yet) re-asserts `EDT<='1'` the next cycle. So `A12004` reads **0x82**, not 0x02 → **return 01**. This is the *same root cause as FLAGS 05* — EDT is a live view, not a latch. On build 36 DMA3 therefore returns at the very first line and reaches none of the later machinery.

**The hang (EDT edge-latch build `e22d454`, disc mounted):** with the edge-latch, line 579 passes (EDT cleared and *stays* cleared → 0x02), so DMA3 proceeds. The MAIN/SUB host sections use fixed loops + `if(...)return` (no infinite loop). The **first blocking wait is the WRAM DMA at test:651** `while(ga->COMSTA[3]!=5)` (then PRG 662, PCM 673, and ~15 more COMSTA waits through 979). Because `COMSTA[3]==5` requires the CDC level-5 interrupt (DTEI→0 → `CDC_INT_N`→0 → `INT_PEND(5)`), any EDT/DTEI mishandling that prevents DTEI from falling for a *memory* DMA leaves that wait spinning forever — the reported "MAIN polls a status forever, SUB idle in its command loop." **Which specific wait hangs, and whether the host section's `0xC2`/`0x82` progression is even reached, depends on the disc-present `DTEN/DTEI/EDT` timing with real buffered sector bytes** — exactly why "validated without a disc showed 03" (test:588, empty buffer → wrong DSR) but "hangs with a disc." Static analysis cannot pin the exact hang line; only a bench that feeds a real sector and runs the real CDC+ASIC reproduces it. Candidate first-hang: **test:651** (first `while(COMSTA[3]!=5)` after a memory DMA in DMA3).

**DMA3 remaining sections** (all reached only past line 579; each is a faithful stimulus the bench should replay): SUB host flags 0x10-0x16 (598-615); cross-read MAIN-vs-SUB 0x20/0x21 (618-641); EDT/DSR for WRAM/PRG/PCM DMA 0x22-0x27 — note the "EDT rises only after reg 004 reading" quirk (644-675); MAIN==SUB host data 0x28 (678-685); buffer wrapping 0x30/0x31 (688-708); DMA-addr no-increment MAIN/SUB 0x32/0x33 vs increment WRAM/PRG/PCM(×2) 0x34/0x35/0x36 (711-759); **two-DMA-without-address-setup 0x37** — this is the block that *inlines* `cdcDmaSetup`'s guts (773-778) and confirms the helper; 1M-mode WRAM 0x38 (788-821); PCM banking 0x39/0x40 (825-844); WRAM mirroring 0x41 (847-860); **FF8004 resets DMA dst addr to 0** 0x42/0x43 (865-879, `mcdRD16(0xFF800A)` must read 0 after `cdcDmaSetup`); WRAM/PRG DMA halt on memory switch 0x44-0x49 (885-942); change-DMA-source-on-the-fly 0x50-0x55 (945-971); PRG WP not honored for DMA 0x56 (973-990); A12008/FF8008 write-skips-words 0x60/0x61, 0x62/0x63 (993-1025).

## L. Non-negotiable fidelity requirements for the bench

1. **Feed real sector bytes** through `CDC_DATA`/`CDC_DAT_WR` with `DECEN=1` (sync+header{00,02,00,01}+"SEGA…", 2352 B). Do **not** stub the decode (`DECEN=0`, preloaded ramp) — the current `tb_cdc.sv` does, which is why its DMA3 "passes" and DMA2 "fails" (inverted).
2. **Model `COMSTA[3]` from `CDC_INT_N`/`INT_PEND(5)`**, cleared on every sub "command" — never hard-code the DMA as instantly complete.
3. **Drive EXT for A120xx and S68K for FF80xx**; let ASIC synthesize `CDC_N/COE_N/CLWE_N/RS`. Byte writes to `FF8004` = UDS (DD/mode); odd-byte to `FF8005`/`FF8007` = LDS (CDC AR/data).

## 1. How the CDC buffer is filled — the CD_WR / DECEN decode path

Two facts frame everything (they are the reason the current bench is unfaithful):

- **The CPU cannot write the CDC buffer at all.** In `CDC.vhd` the buffer write bus is driven from exactly one place each:
  - `RAM_DO <= DEC_DAT;` (line 425) — the only driver of write data.
  - `RAM_WE <= DEC_WR and DEC_WR_EN and CTRL0(DECEN);` (line 457) — the only driver of write-enable.
  There is **no CDC register that writes buffer data.** Registers R2/R3 (DBC), R4/R5 (DAC), R8/R9 (WA), R12/R13 (PT) only set *address/counter* values. So the only way bytes enter the buffer is the sector-decode path below.

- **The decode path is gated by DECEN, WRRQ and clocked by CD_WR edges under the CE-gen enable EN.** `EN <= ENABLE and (CLKEN_N or CLKEN_P);` (line 174), where `CLKEN_P/N` are the sub-CPU clock enables `S68K_CE_R/F` produced by ASIC. The whole decode block (lines 357–419) sits inside `if EN = '1'`.

### Edge detect and word counter (lines 357–421)
```

if CTRL0(DECEN) = '1' then
  CD_WR_OLD <= CD_WR;                           -- line 360
  if CD_WR = '1' and CD_WR_OLD = '0' then       -- line 361  one word per rising edge
     DEC_DAT <= CD_DI;                          -- latch the incoming 16-bit word
     DEC_POS <= RAM_POS;                        -- buffer offset for THIS word
     WORD_CNT <= WORD_CNT + 1;                  -- line 365
     ...
```
`WORD_CNT` counts 16-bit words as they arrive on `CD_WR` rising edges. At edge *k*, the current value of `WORD_CNT` is *k* (0 on the first edge). The `case`-like ladder tests that current value:

| `WORD_CNT` (word index) | Sector byte pair | Action | Buffer offset written (`RAM_POS`) |
|---|---|---|---|
| 0 … 5 | bytes 0–11 (sync) | nothing written | — |
| **6** (`=12/2`) | bytes 12,13 | `DEC_HEAD01<=CD_DI`; if WRRQ=0 also `HEAD0/HEAD1`; `DEC_WR<='1'` | 0 → then `RAM_POS+=2` |
| **7** (`=14/2`) | bytes 14,15 | `DEC_HEAD23<=CD_DI`; if WRRQ=0 also `HEAD2/HEAD3`; `DEC_WR<='1'` | 2 → `RAM_POS+=2` |
| **8 … 1031** (`16/2 … (16+2048)/2-1`) | bytes 16–2063 (2048 user bytes) | `DEC_WR<='1'` each edge | 4 … 2050 |
| 1032 … 1174 | bytes 2064–2351 (EDC+ECC) | nothing written | — |
| **1175** (`=2352/2-1`) | bytes 2350,2351 | `IFSTAT(DECI)<='0'; STAT3(VALST)<='0'; SECTOR_END<='1'` (lines 389–391); reset `WORD_CNT`,`RAM_POS` to 0 (394–398) | — |

`RAM_WE = DEC_WR and DEC_WR_EN and DECEN` (line 457). `DEC_WR_EN` follows `CTRL0(WRRQ)`. **So the buffer is populated only when DECEN=1 AND WRRQ=1.** With WRRQ=1, at sector end (`WORD_CNT=1175`, lines 403–412) the write pointers advance: `WA <= WA+2352`, **`PT <= PT+2352`**, and `HEAD0..3` are latched from `DEC_HEAD01/23`.

### Buffer address and the RAM (lines 423–425, 457, 642; `MCD.vhd` 425–435)
```
DEC_ADDR <= PT + 2352 + DEC_POS;   -- write byte address
RAM_A_WR <= DEC_ADDR(15 downto 1); -- word address (write port B, 16-bit)
RAM_DO   <= DEC_DAT;               -- the 16-bit word
RAM_A_RD <= DAC;                   -- read byte address (read port A, 8-bit)
```
`CDC_RAM` is `dpram_dif` generic `(14,8,13,16)` — a **16 KB** buffer (14-bit byte read address, 13-bit word write address), byte-read / word-write. It is an Altera mixed-width `altsyncram` (`bram.vhd` 158–244), so **even byte address ↔ low byte `data_b(7:0)`, odd ↔ high byte `data_b(15:8)`**. Both the write pointer and DAC wrap modulo 16 KB (this is the “cdc buff wrapping” test, `test_cdc_new.c` line 696 uses `PT + 16384 - 128`).

Because `PT` is advanced by 2352 *after* the sector is written at `PT+2352+offset`, the post-decode `PT` value the verificator reads back **equals the buffer address where the sector data starts**. `cdcDmaSetup(..., PT)` loads `DAC=PT`, and the DMA reads exactly the bytes just decoded.

### Where the header and data land (definitive)

## 3. EDT/DSR semantics — hardware truth vs the code

**Ground truth** is the sequence `testCDC_dma3` asserts for a MAIN transfer (byte at A12004 = `EDT·0x80|DSR·0x40|DD`, DD=2):

| step | A12004 | meaning |
|---|---|---|
| after `cdcDmaSetup` (FF8004 written), before DTTRG | `0x02` | EDT=0, DSR=0 |
| after DTTRG + a few cycles | `0x42` | DSR=1, first word ready |
| while ≥2 words remain (reads keep refilling) | `0x42` | DSR stays 1, EDT=0 |
| when exactly the **last** word remains | `0xC2` | EDT=1 **and** DSR=1 |
| after last word read | `0x82` | EDT=1, DSR=0 (all data read) |
| further reads | `0x82` | **persists** (checks 0x06, 0x07) |

So the real semantics:
- **DSR** = "a host word is waiting at A12008/FF8008". Set when the gate array assembles a word; cleared by the CPU's host‑data read (`MAIN_CPU_CDC_READ`/`SUB_CPU_CDC_READ`). Pulses once per word.
- **EDT** = "End of Data Transfer": a **sticky level** raised when the CDC has streamed its last byte (`DBC`→0, the `CDC_DTEN_N` 0→1 completion event), and **held 1 until the next DMA setup** (a FF8004/FF800A write → `DMA_ADDR_SET`). The completion detector the software trusts is: poll A12004 until EDT=1 and it stays (see `testCDC_dma1:395` `while ((REG08_A12004 & EDT)==0)`), or use the CDC DTEI L5 IRQ (`sub_bios` IE5 → `COMSTA[3]=5`, polled by the `while(ga->COMSTA[3]!=5)` loops in dma3). (The verificator author even noted at line 652: *"EDT rise only after reg 004 reading"* — EDT is a level observed through A12004, not a one‑shot.)

**Current code (build 36, level EDT).** `EDT<='1'` is re‑evaluated every idle cycle where `CDC_DTEN_N='1'` (line 419). This is **too eager**: right after `cdcDmaSetup`, before DTTRG, the CDC is idle (`CDC_DTEN_N=1`), so one cycle after `DMA_ADDR_SET` cleared it, EDT is driven back to 1 → A12004 reads `0x82`, not the required `0x02`. That is exactly build 36's benign **DMA3 ERROR 01** (`if (REG08_A12004 != 0x02) return 0x01`, line 579). The level version is wrong on the *value* but **never hangs**: after any `DMA_ADDR_SET` clears EDT, the next idle cycle restores EDT=1, so any "wait for EDT" always eventually succeeds. The suite completes.

## 4. Why the e22d454 EDT edge‑latch hangs DMA3 with a disc

The edge variant replaces the level assignment with: latch `OLD_CDC_DTEN_N`, set `EDT<='1'` **only** on `OLD_CDC_DTEN_N='0' and CDC_DTEN_N='1'` (the one completion edge), clear `EDT<='0'` **only** on `DMA_ADDR_SET`, otherwise hold. This fixes the value right after setup (EDT reads 0 → passes check 01) but turns EDT into a **fragile one‑shot with no recovery path**:

- EDT can only ever be re‑armed by a fresh `CDC_DTEN_N` 0→1 **edge**. Between transfers `CDC_DTEN_N` sits at 1 (level, no edge).
- The verificator issues `DMA_ADDR_SET` pulses **around/after** completion: every `cdcDmaSetup` writes FF8004, and the WRAM/PRG/PCM sub‑tests additionally write **FF800A** (`test_cdc_new.c:648,659,670,691,697,714,725,737…`). Each such write forces `EDT<='0'`.
- So once the completion edge has latched EDT=1, **any later `DMA_ADDR_SET` clears it, and because `CDC_DTEN_N` is already parked at 1 (the transfer is over), no new 0→1 edge will ever occur to set it again.** EDT is stuck at 0 permanently.

Consequence: the MAIN's completion poll never satisfies. Concretely it reaches DMA3's first hardware‑DMA sub‑test (WRAM, lines 644‑653) which build 36 never reaches (build 36 bailed at 01) and spins in `while (ga->COMSTA[3] != 5)` / a `A12004 & EDT` poll forever, issuing no SUB command — which is exactly the observed telemetry: **MAIN spinning on a status read, SUB idle in `sub_bios` `cmd_rx` polling COMCMD0/FF8010**. The level version does not hang here because its EDT self‑restores after every spurious `DMA_ADDR_SET`.

**Disc dependence** matches too: without a disc `DECEN=0`, the CDC has no real sector/DTEN timing, so the intermediate flag checks (`0x42/0xC2/0x82`) don't line up and `testCDC_dma3` **returns early at 0x03** (line 588) *before entering any polling loop* — hence e22d454 "validated" as DMA3=03, no hang. With a disc the real per‑sector `CDC_DTEN_N` transitions and DTEI make the early checks pass, the test advances into the polling loop, and the stuck‑at‑0 EDT then hangs it. **[inferred]** re: which specific loop, since I cannot run e22d454; certain part is the EDT stuck‑0 mechanism above.

## 5. Why the ccb6fdf DMA_BYTE‑reset also hangs DMA3 (separate cause)

That commit added `DMA_BYTE<='0'` to the `DMA_ADDR_SET` block (398‑402). During DMA3 the verificator pulses `DMA_ADDR_SET` (FF800A/FF8004) while a word is half‑assembled (`DMA_BYTE=1`, high byte captured, low byte pending). Forcing `DMA_BYTE<=0` mid‑word makes the next CDC byte be stored as a **new** high byte: the word is never completed, `DSR` never sets, `DBC` never reaches 0, so the CDC **DTEI never fires** → `while(ga->COMSTA[3]!=5)` hangs. It "fixed DMA2" because DMA2 leaves a stale `DMA_BYTE=1` between transfers that the reset clears; DMA3 interleaves `DMA_ADDR_SET` with live word assembly, so the same reset corrupts it. This is a byte‑alignment/FSM defect, distinct from the EDT‑latch defect, but both are triggered by the shared `DMA_ADDR_SET` being pulsed mid‑DMA3.

## 6. What a faithful bench MUST drive and observe (the contract this defines)

To distinguish "passes" (level, build 36) from "hangs" (edge‑latch, DMA_BYTE‑reset), the bench cannot stub the CDC or approximate the register stream. It must:

1. **Feed real sector bytes through `CD_DI`/`CD_WR` with `CTRL0(DECEN)=1`** (the `CDC_DATA`/`CDC_DAT_WR` path in MCD.vhd:415‑416), so the CDC decodes a 2352‑byte sector into its buffer RAM and produces a hardware‑faithful `CDC_DTEN_N` waveform — asserted `0` for the whole `DBC`‑byte host transfer, one clean 0→1 completion edge when `DBC`→0, coincident with `IFSTAT(DTEI)` → `CDC_INT_N` (SUB L5). A preloaded ramp with `DECEN=0`/`CD_WR=0` cannot generate this and is why the old bench inverted its verdicts.

2. **Replay the exact MAIN/SUB register sequence** of `testCDC_dma3`, not an approximation:
   - SUB: CDC reset, `IFCTRL=DOUTEN|DTEIEN`, set `DBC`(=len−1)/`DAC`/`PT`, write **FF8004 = DD** (→ `DMA_ADDR_SET`, EDT clear), optionally **FF800A** (→ `DMA_ADDR_SET` again), then CDC **R6 DTTRG** via FF8007 (→ `IFSTAT(DTBSY)<=0`, transfer starts).

   - Crucially, **issue the interleaved FF800A/FF8004 writes mid‑DMA3** — those `DMA_ADDR_SET` pulses are the trigger that exposes both bad variants.

3. **Assert on the exact ground‑truth values** in the table of §3 (MAIN `0x02/0x42/0xC2/0x82`, SUB `0x03/0x43/0xC3/0x83`, WRAM `0x87`, PRG `0x85`, PCM `0x84`), and — the acceptance criterion that catches the hang — **assert the polling loops terminate within a bounded cycle budget**. A correct EDT is a sticky level cleared only by `DMA_ADDR_SET` *at setup* and set at the `CDC_DTEN_N` completion edge, that also survives a `DMA_ADDR_SET` pulse issued *after* completion (or the bench must at minimum flag "EDT never re‑asserts after a post‑completion DMA_ADDR_SET" as the hang signature). ## 2. FIDELITY BREAK #1 — the CD sector-decode path is stubbed out (the central defect)

The real data path (confirmed in `CDC.vhd` and `MCD.vhd:415-416`): Main streams sector words over ioctl index 0x02 → top-level `CDC_DATA`/`CDC_DAT_WR` → `CDC.CD_DI`/`CDC.CD_WR`. Inside `CDC.vhd` (lines 359-414) the decoder runs **only when `CTRL0(DECEN)=1`**: each `CD_WR` rising edge consumes one 16-bit word, `WORD_CNT` walks 0…1175, the header words land in `HEAD0-3`, the 2048 user bytes are written to buffer RAM through `DEC_WR`/`RAM_WE` (gated by `DEC_WR_EN=CTRL0(WRRQ)`), and at `WORD_CNT=2352/2-1` it advances `PT`/`WA` by 2352, pulses `SECTOR_END`, and drops `IFSTAT(DECI)`/`STAT3(VALST)`. The host-transfer FSM (`TS_*`, lines 544-607) then reads that RAM at `RAM_A_RD=DAC` and drives `HDO/DTEN_N/WAIT_N` and the `DBC` underflow → `DTEI`.

The bench bypasses all of it:

- `CDC.CD_DI=16'h0000, CDC.CD_WR=1'b0` (`tb_cdc.sv:188`) — **no sector is ever fed**.
- `tb_cdcram` is **preloaded with a ramp** `mem[i]=i[7:0]` (`tb_cdc.sv:47-49`), and the reference `buffref(i)=ramp(PT+i)` with `localparam PT=0` (`tb_cdc.sv:210-217`).
- `CTRL0(DECEN)` is **never set** anywhere in the bench (no `cdcDecoderON`, no `CTRL1(SYIEN)`), so the decoder, the 75 Hz frame timer (`CDC.vhd:434-455`), `DECI`, `SECTOR_END`, and the `PT/WA` auto-advance **never run**.

Consequences that directly falsify verdicts:

1. **`PT` is forced to 0 and never read back.** The real verificator computes `PT` by reading the CDC `HEAD0`/`PT` registers after a real decode (`test_cdc_new.c:94-99`), then every `cdcDmaSetup(..., PT)` and buffer-wrap test (`test_cdc_new.c:696` uses `PT+16384-128`) is *relative to that PT*. Wrap-around, `DAC` addressing across the 14-bit buffer, and PT‑relative offsets are never exercised.
2. **The host FSM's end-of-transfer state is wrong.** `DTEN_N`/`IFSTAT(DTEN)`/`DTBSY`/`DBC`-underflow timing in `CDC.vhd` depends on the real buffer + `DAC` walk. Because the ASIC re-derives `EDT` from `CDC_DTEN_N` every idle clock (`ASIC.vhd:405-420`: in `DS_IDLE`, `EDT<='1'` while `CDC_DTEN_N='1'`, `EDT<='0'` while `='0'`), the *entire* EDT/DSR trajectory the FLAGS and DMA3 tests inspect is a function of the CDC transfer-done state — which the stub falsifies. This is the mechanism behind **FLAGS 02-vs-05** (§5) and **DMA3 PASS-vs-01** (§6).
3. **`tb_cdcram` is not bit-equivalent to `dpram_dif(14,8,13,16)`** (`MCD.vhd:425-432`). The real write port is 13:1 addressed, 16-bit; the read port 14:0, 8-bit. `tb_cdcram` (`tb_cdc.sv:39-57`) fakes a plausible byte split but is never validated against the decoder's actual `RAM_A_WR/RAM_DO/RAM_WE` writes because the decoder never writes. Once real decode is fed, this model must match `dpram_dif` byte lanes exactly.

**This single break is why the buffer never contains real data and why every EDT/DSR/PT/DBC interaction is off.** No register-sequence tweak can compensate; the sectors must be fed.

## 4. FIDELITY BREAK #3 — completion detection: `CDC_INT_N` substituted for the real handshake

The verificator has **two** distinct completion mechanisms, and the bench models neither faithfully:

- **Memory DMAs (WRAM/PRG/PCM):** the C code polls `while (ga->COMSTA[3] != 5)`. `COMSTA[3]` (=`A12026`/`FF8026`, ASIC `CS(3)`) is **written by the sub-CPU's level-5 CDC IRQ handler** (sub_bios/sub_app), which only runs when `CDC_INT_N` asserts *and* the sub has `IEN(5)` set (`SUB_REG_IEMASK`, `test_cdc_new.c:87`) *and* `INT_PEND(5)` fires on the `CLK_12M_F` edge (`ASIC.vhd:1300-1311`). The bench replaces this with `wait_dma_done` = "wait for `CDC_INT_N` low" (`tb_cdc.sv:375-379`). That skips the sub-CPU IRQ latency, the `IEN(5)` mask gate, and the fact that `COMSTA[3]` is a *software* value — and it means the FLAGS "irq should only fire on DTEI falling edge / respects mask" sub-tests (`test_cdc_new.c:1138-1163`) can never be reproduced.
- **Host DMAs to MAIN/SUB (DMA3, DMA1 first loops):** there is *no* `COMSTA` poll — completion is detected by the MAIN reading data from `A12008`/`FF8008` and polling `A12004`/`FF8004` EDT/DSR. **This is the loop that hangs.** The bench's `test_dma3_main` does single `if` checks, never a `while`-poll, so it structurally cannot reproduce the hang.

Because `COMSTA[3]` is sub-software state, a bus-task bench that does not run the sub cannot produce it *the real way*. Two faithful options (either is acceptable, the second is closest to the task's intent):
- Model the sub's IRQ5→`COMSTA[3]=5` behaviour explicitly (a small tb process that, gated on `IEN(5)`, writes `CS(3)=5` on the `CDC_INT_N` falling edge exactly as the sub BIOS does), **or**
- Replace `while(COMSTA[3]!=5)` with a **bounded** wait on the true underlying condition (`INT_PEND(5)`/`CDC_INT_N` with the `IEN(5)` gate) **that reports HANG on timeout** rather than silently substituting.

Either way the *host* (MAIN) poll loops must be modeled as real bounded polls (§6).

## 5. FIDELITY BREAK #4 — test order and inter-test state coupling are not preserved (this is why FLAGS reports 02, not 05)

The verificator runs **init → flags → dma2 → dma3 → dma1** (`test_cdc_new.c:22-41`), each followed by `tsetCDC_end`. The bench runs **dma1 → flags → dma2 → dma3** (`tb_cdc.sv:528-531`) and, crucially, resets the decoder path between tests via `cdc_end` while the gate-array `EDT/DSR/DD/DMAA/DS` and the CDC `DTEN_N/DTBSY/DBC` carry residual state that the bench's stub gets wrong.

The FLAGS 02-vs-05 inversion is a direct symptom. In the real RTL, `EDT` is **not** a latch — in `DS_IDLE` it continuously tracks `CDC_DTEN_N` (`ASIC.vhd:405-420`), and `DMA_ADDR_SET` (asserted by *both* `FF8004` and `FF800A` writes, `ASIC.vhd:912-922`) only forces `EDT<='0'` for a single clock (`ASIC.vhd:398-402`). On hardware the CDC finishes the WRAM DMA with `CDC_DTEN_N=1`, so after the `FF800A=0` write `EDT` snaps back to 1 → the verificator's err02 check (`EDT` must still be set) *passes*, and it proceeds to err05 (`FF8004` fails to clear the — non-existent — latch). In the bench, the stubbed CDC leaves `DTEN_N`/`DTEN` in a different state at that instant (transcript shows `A12004=0x07`, EDT=0 after `FF800A`), so it fails early at err02. The *code path in `test_flags` is faithful* (§3) — the wrong verdict comes entirely from the stubbed CDC transfer-done state plus not reproducing the preceding init/flags/dma2 history. Fix the decode path (§2) and the order/coupling, and this check will track hardware.

## 6. FIDELITY BREAK #5 — DMA3 is truncated to its flag prologue; the hanging poll loops are absent

`test_dma3_main` (`tb_cdc.sv:454-471`) implements only the first ~18 lines of the real `testCDC_dma3` (the MAIN EDT/DSR flag walk, `test_cdc_new.c:577-595`) and returns. It omits, among others:

- the WRAM/PRG halt-during-access tests (885-943).

The hang the task describes lives in these omitted sections: MAIN triggers a host DMA, then `for(...) tmp=REG16_A12008;` drains data while `while` conditions poll `A12004` EDT/DSR — and with the EDT edge-latch RTL, EDT never reaches the expected value, so a poll spins forever. The bench already has the timeout primitive (`TIMEOUT`, the watchdog); it just needs to wrap the *real* poll loops with it and classify "never satisfied" as HANG rather than as an arbitrary error code or a pass.

## 7. FIDELITY BREAK #6 — behavioural memory models and bus-cycle protocol approximations

These matter once the decode path is faithful, and at least one already causes a false failure today:

- **Word-RAM interleave (false DMA2 03).** The DMA writes 2M-mode word RAM through the ASIC `WRA_*` machines (`ASIC.vhd:1767-1804`, `1914-1951`) into two banks (`wordram0`/`wordram1`, even/odd word by `DMA_ADDR(1)`), each a plain `tb_spram` (`tb_cdc.sv:198-205`). The bench's `wram_byte()` reader (`tb_cdc.sv:219-224`) assumes `w=b>>1; bank=w&1; addr=w>>1; hi=~b[0]` — a hand-derived mapping that must exactly match how the ASIC's `WR0A/WR1A` split `DMA_ADDR(17:2)` and the byte lanes. The transcript's DMA2 **ERROR 03** (first full-sector compare) with a *ramp* buffer strongly implicates this mapping (and/or the `+8` byte offset handling at `DMA_ADDR(1:0)`), not the RTL — i.e. a **false failure** manufactured by the model. This must be validated against a known DMA of known bytes before any RTL verdict is trusted.
- **`tb_cdcram` vs `dpram_dif`** byte lanes (§2.3) — validate once real writes occur.
- **PRG-RAM / PCM-RAM / SUB destinations are not modeled at all.** `ASIC.PRG_DI=0`, `PCM` is stubbed, `CD_DI/CD_SC_WR=0`, `PRG_RDY/PCM_RDY/ROM_RDY=1` (`tb_cdc.sv:160-173`). So DMA2/DMA3's PRG and PCM sub-tests (which return 05/06-12/24-27/35-40 on hardware) cannot run. The odd-length "05" the hardware reports in DMA2 could be the WRAM *or* PRG path; without those destinations the bench can't disambiguate.
- **Fabricated bus timing.** `s68k_wr8/rd` use fixed `repeat(6)`/`repeat(4)` waits (`tb_cdc.sv:247-284`); `ext_rd/wr` use `EXT_GAP=150` idle clocks and fixed `repeat(3)/(8)` (`tb_cdc.sv:292-325`). Real cadence is set by the 68000 and by the ASIC's `DTACK` handshakes. Because the CDC samples strobes on EN edges and the DMA FSM advances on `DS_*`, the exact spacing changes which words the MAIN captures — the verificator relies on this (e.g. DMA3's "wr ops skip words", 994-1025). These counts need to be derived from `DTACK`/`AS` handshake completion, not hand-tuned constants.
- **Sub-CPU CE cadence.** The CDC's `CLKEN_P/N` come from the ASIC's `S68K_CE_R/F`, driven by `CLK50_EN` and the `CLK_CNT` phase counter (`ASIC.vhd:306-316`). The bench's `en50` divider must produce the same 12.5 MHz sub-CPU phase the real core does, or the CDC's `WR_F/RD_F` edge capture and the `DT_EN` toggle (`CDC.vhd:459-472`, host transfer advances only when `DT_EN=1`) run at the wrong rate relative to the MAIN EXT accesses.

## 8. Concrete change list to make the bench faithful

**A. Feed real sectors through the decode path (fixes the central break, §2):**
1. Provide a real 2352-byte sector (or a handful) as `CD_DI` words. Load from a file or embed a known Mode‑1 sector whose header is `00 02 00 01` "SEGA…" like the verificator's reference (`test_cdc_new.c:126`).
2. Add a tb driver that, after `cdcDecoderON` (i.e. after the sub writes `CTRL0=DECEN|WRRQ|AUTORQ` and `CTRL1=SYIEN|SYDEN|…`), pulses `CDC.CD_WR` once per 16-bit word at the real 75 Hz/one-sector-per-frame cadence, driving `CDC.CD_DI`. ## Why (a) is sufficient and faithful — the four load-bearing findings

**1. The sub‑CPU is a transparent relay during these tests; driving `S68K`/`EXT` as bus tasks is behaviourally identical to running `sub_bios.s`.**
`mcdInit()` loads `sub_bios.s` (NOT `sub_app.s` — the CDBIOS one is never used by the CDC suite). `sub_bios.s` is a pure command interpreter: it polls `COMCMD0` (`FF8010`) and, per command, does exactly one `move.b/move.w` to the address the MAIN handed it (`rd_b/wr_b/rd_w/wr_w`), plus IRQ handlers `IE4`/`IE5` that only *record* interrupts into `COMSTA`. So every `cdcRegSelect/cdcRegWrite/cdcDTACK/dttrg/mcdWR8(0xff80xx)/mcdRD16(0xff8008)` is just a relayed `FF80xx` bus access. The gate array cannot tell a real sub‑68000 from a bus task issuing the same `S68K` cycle. Hardware telemetry already confirmed the sub sits **idle in `cmd_rx`** during the DMA3 hang — it contributes no autonomous state to the DMA machine.

**2. `COMSTA[3]==5` (the status the MAIN "polls forever") is exactly `CDC_INT_N` asserting (DTEI).** Memory‑DMA completion is signalled: DMA done → CDC raises DTEI → `CDC_INT_N` low → sub level‑5 IRQ → `IE5` writes `STA_IRQ=5` → MAIN sees `COMSTA[3]==5`. The bench watches `CDC_INT_N` directly instead of emulating the relay. A DMA that never raises DTEI = `CDC_INT_N` never asserts = the hang, made directly observable. This is the single most important equivalence — it lets (a) reproduce the poll‑forever hang without a sub‑CPU.

**3. The real fidelity fix is the sector‑decode path, and it is cheap.** `testCDC_init` requires REAL decoded data: header must read back `00 02 00 01` and `PT` is derived from the decode. In RTL, data enters only when `CTRL0(DECEN)=1` and `CD_WR` pulses (`CDC.vhd:359-414`): word 6/7 → HEAD, words 8..1031 → user data, `WORD_CNT=1175` → DECI/SECTOR_END. The bench must **feed a real 2352‑byte Mode‑1 sector through `CD_DI/CD_WR`** (12 sync, header `00 02 00 01` at bytes 12‑15, `"SEGA"…` at byte 16) and let `CDC.vhd` decode it into the buffer RAM. This is faithful (it is literally what the HPS `cdc_dat_download → CDC_DATA/CDC_DAT_WR` path does on hardware), and it lets `DBC/DAC/DTEN/EDT/DSR` run against genuinely decoded data. No CDD/TOC emulation is needed — driving `CD_WR` directly *is* the sector stream; the CDD play sequence is just hardware's way of causing that stream.

**4. The host DMA read never wedges the bus — the hang is purely software poll loops.** `A12008/A12004` reads assert `M68K_REG_DTACK_N=0` unconditionally (`ASIC.vhd:659-702`) and return the current `HD`/flags. So the hang is never a stuck bus cycle; it is always a `while(COMSTA[3]!=5)` or `while((A12004&EDT)==0)` that never satisfies. The bench models these as bounded waits with timeout.

### Why the current `tb_cdc.sv` gives inverted/false verdicts (the two shortcuts to delete)
- It ties `CDC.CD_WR=1'b0`, `CD_DI=0` (`tb_cdc.sv:188`) and preloads `tb_cdcram` with a ramp — the decoder never runs, so DBC/DAC/DTEN timing is not driven by a real sector.
- It replays an *approximated* register sequence and models A12004 flag evolution as `02→42→…→82`, which is why it "passes" the DMA3 that hardware fails at the first check (`return 0x01`) and "fails" the DMA2 that hardware passes. Its only hang handling is a global `$finish "WATCHDOG"` — it never classifies a hang as a hang.

```systemverilog
// CS(3) is SUB-written (ASIC 958-961); with no sub the bench models it:
logic [7:0] comsta3 = 0;
logic       ien5    = 0;           // bench's copy of IEN(5), tracked from IEMASK writes
logic       cint_old = 1;
always @(posedge CLK) if (en_tick) begin        // en_tick = (S68K_CE_R|S68K_CE_F)
   cint_old <= CDC_INT_N;
   if (CDC_INT_N==1'b0 && cint_old==1'b1 && ien5) comsta3 <= 8'd5; // DTEI/DECI edge
end
// cmd_rx clears STA_IRQ at the top of EVERY relayed sub command:
//   -> in s68k_wr8/wr16/rd to any FF80xx address, set comsta3<=0 at cycle start.
//   -> mcdRD16(0) (INIT) is a null command: task cmd_null(); comsta3=0; endtask
// IEMASK writes: in the FF8032 write path, set ien5 = val[5], ien4 = val[4].

// --- poll-until-condition-or-HANG ---
// returns HANG(label) if COMSTA[3] never reaches 5 / EDT never sets within budget.
localparam int POLL_BUDGET = 4_000_000;   // CLKs; one 2352 DMA completes in far fewer
task automatic wait_comsta5(input string label, output bit hung);
   int t=0; hung=0;
   while (comsta3 != 8'd5) begin @(posedge CLK); if (++t>=POLL_BUDGET) begin hung=1; break; end end
   if (hung) $display("  >>> HANG @ %s (COMSTA3 poll, waited %0d clk, DS/EDT/DTEI stuck)", label, t);
endtask
task automatic wait_edt(input string label, output bit hung);   // models while((A12004&EDT)==0)
   int t=0; hung=0; logic [7:0] v;
   forever begin ext_rd8_hi('h12004,v); if (v & EDT) break; @(posedge CLK); if (++t>=POLL_BUDGET) begin hung=1;break; end end
   if (hung) $display("  >>> HANG @ %s (A12004&EDT poll, last=%02h)", label, t /*and v*/);
endtask
```

Any `hung` propagates up as the test result `HANG` (see §4). Below, each `while(COMSTA[3]!=5)` in the C becomes `wait_comsta5("<label>",hung); if(hung) begin err=HANG; return; end`.

## (4) REPORTING — PASS / ERROR nn / HANG per test

Three outcomes, printed in the verificator's own idiom so sim ↔ hardware telemetry compare 1:1:
```
task run(string name, ref-task body):
   err = body();                       // err: 0=pass, 0x01..=error code, HANG=sentinel (e.g. 'h100)
   tsetCDC_end();                      // between tests, EXCEPT after INIT (match suite order)
   if      (err==0)    $display("  CDC %-6s OK", name);
   else if (err==HANG) begin $display("  CDC %-6s HANG", name); hangs++; ABORT-this-test; end
   else                $display("  CDC %-6s ERROR %02h", name, err);
```
- Order: **INIT → FLAGS → DMA2 → DMA3 → DMA1**, `tsetCDC_end` after each except INIT; INIT failure aborts the suite (`if(resp)return 1`).
- A `HANG` prints the sub‑test label + last polled value and **stops that test** (never `$finish` as a pass, never continue silently). The global watchdog (tb_cdc.sv:538) stays as a backstop but must not be the primary mechanism.
- Bus‑task DTACK timeouts (already present, 252/264/279/309/321) → on expiry print `HANG (bus wedged @ <addr>)`.
- End line: `======== N error(s), M hang(s) ========` then a **self‑validation verdict** (§5).
